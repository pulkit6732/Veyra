# Architecture

`index.html` (responsive browser UI) → `veyra.py` (stdlib threaded HTTP + application functions) → SQLite file. No ORM or external package. Each modifying HTTP operation enters `BEGIN IMMEDIATE`: SQLite serializes writers across threads/processes; the delivery commit reads version, stock and evidence and writes the decision, decrement and unique movement within the same transaction. A preflight decision is never trusted at commit. A failed transaction rolls back all its changes. The database enforces unique references, nonnegative stock and quantity checks. Server binds to localhost by default.

Evidence count session snapshots `(SKU, location, version, recorded qty, actor, start time)` before physical counting. Submission is append-only evidence with observed qty and captured version, plus status STALE, VERIFIED or DISCREPANCY. `evidence.status` is a snapshot of submission conditions, not proof of future freshness: delivery always compares captured version to current version. If multiple counts at current version disagree, the order is held; an explicit stock adjustment increments the version, after which workers can recount. Investigation reads the count snapshot, current version, last earlier verified count, relevant bin/version movements and any resolution from persisted tables; event types are evidence, never causal proof. The operator can record a note and explicitly reconcile the latest current discrepant count to its observed quantity; this inserts a movement and resolution atomically and bumps the version, so recount is still mandatory. No automated discrepancy adjustment or causal inference. Both allowed and blocked preflight/commit attempts persist to `decisions`; successful delivery persists one `movements` row. A repeated completed order with identical payload returns ALREADY_COMPLETED (no second movement); a conflicting ref is rejected.

Limits: operations are single-SKU documents; no role-specific permissions, OTP, server push, background job or production TLS. `BEGIN IMMEDIATE` trades concurrent write throughput for simple correct local serialization. SQLite doesn't offer row-level locks; multi-process writers are serialized on the database write lock. Human counts cannot establish actual physical truth without trusted measurement. Count conflict policy is conservative, no supervisor override currently.
