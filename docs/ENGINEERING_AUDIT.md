# Engineering audit (local SQLite deployment)

Scope: `veyra.py`, `index.html`, Python/API/browser tests, README, requirements/API/architecture/database docs, and commits 4017753, 1672ed7, 339c606. No README or LICENSE changes. Test fixtures are local, not evidence of physical accuracy.

## Findings and decisions

- Final commit remains a `BEGIN IMMEDIATE` writer transaction. Every line is checked against the then-current stock row, count version and same-version conflicts before any line is deducted. Blocked decisions persist; a failed write rolls back all deductions, decisions, movements, events and state. A competing commit does not get to use an earlier preflight. Same-version conflicting observations still block even if the most recent agrees. Tests use same-process threads (including count submission racing with a commit) and injected SQLite failures, not a multi-process/power-loss test.
- Before this audit: rollback journal (no WAL PRAGMA), foreign keys ON and busy timeout 15,000 ms per connection, every GET acquired a write reservation, and investigation GET could create stock via `scope()`. GETs now take one deferred read snapshot and do not create rows; WAL is enabled at initialization, with the same FK/timeout and per-request connection close. A reader/writer test verifies snapshot isolation while the reader is open and the writer finishes; it is not a throughput benchmark. WAL permits one writer and concurrent readers, but can report SQLITE_BUSY and can grow if readers delay checkpoints. Do not use the live main-file-only copy as a backup.
- Previous delivery-list batching (committed in 1672ed7) used three SELECTs regardless of order count, but its evidence hint treated a *later-submitted stale count* as if it hid an earlier current-version count. The final gate did not have this bug. The list now chooses a current-version count first and falls back to latest history; disagreement among current counts still takes precedence. These are display hints, not authorization.
- Investigation's scoped movement version predicate previously searched via `ix_movements_product` (all movements for a product). Two version/scope indexes now allow `MULTI-INDEX OR` on source/destination. A separate index covers latest evidence ID per bin without a temporary sort. Indexes increase insert and disk cost. No pagination rewrite or speculative query caching.
- Existing count sessions represent OPEN and SUBMITTED with immutable submitted evidence. Conflict, resolution, and recount are inferred from current-version evidence, explicit adjustment and a *new* session; a single status column would not safely describe simultaneous conflicting observations. No second task-state machine was added.
- No reservation/allocation: PICK/PACK are not a claim on stock. Competing deliveries are serialized at final commit. Reservation would require an independently specified allocation time, reference/idempotency contract, cancellation (not supported today), and policy for transfers, direct adjustments, resolution, and count observations. Making available stock authoritative ahead of the evidence gate risks changing its semantics. Current available-to-commit is simply on-hand **at final validation**, not on-hand minus a reserved balance. Preflight and the UI cannot promise fulfillment. Reservation/race/cancellation tests are inapplicable until that policy exists.
- Known opening balance + full ordered version chain of RECEIVE/TRANSFER/DELIVER/ADJUST movements, evidence, decisions and linked events support reconstruction of recorded operations. `ADJUST.qty` is an absolute resulting balance (not a delta). Follow-up: an `opening_balances` table now records an explicit OPENING_BALANCE checkpoint at stock-row creation (seed at v0), or at upgrade for stock rows already present. The checkpoint includes a movement-ID watermark: replay only later movements, checking the per-scope version chain. This does not invent an earlier opening for migrated history or alter stock versions, counts or delivery policy. Previous movement history can remain unexplained before the upgrade checkpoint. Gaps in the later version chain, manually edited DBs, or bounded API lists prevent a complete historical explanation. The causal reason for a physical variance cannot be reconstructed. Tests replay from the persisted checkpoints and check migration rollback and idempotency.
- Persisted `dashboard.held_decisions` counts blocked *attempt rows*, including preflight; it does not count unique blocked orders. No new metrics: discrepancy rate and resolution time require definitions/denominators, while UI lists truncate to 200. Avoid portraying counts of application records as business outcome measures.

## Query measurements

Measured with SQLite trace on a disposable DB containing 13 one-line PACKED documents, one stock row (100 units, v0) and one agreeing v0 count; one successful commit of 1 unit. Count only SQL SELECT/WITH and INSERT/UPDATE/DELETE statements inside each operation, excluding transaction control and authentication. Read response shapes checked (13 documents, one inventory row, a current investigation, completed commit); final-gate and hint equivalence under a later stale submission are tested separately. Index plans inspected with `EXPLAIN QUERY PLAN`. This is not latency, throughput or a large-scale benchmark.

| Path | Before: reads / writes | After: reads / writes |
| --- | ---: | ---: |
| Delivery list (13 orders, 13 lines) | 3 / 0 | 3 / 0 |
| Inventory list (1 row) | 1 / 0 | 1 / 0 |
| Count start | 3 / 2 | 3 / 2 |
| Investigation, current evidence | 10 / 1 | 10 / 0 |
| One-line delivery commit | 5 / 5 | 5 / 5 |

Before measurements used the same fixture and traced direct functions; the earlier investigation measurement had 11 total statements (10 reads, 1 write). Baseline plan: latest-evidence lookup needed a temp B-tree; scoped movement query searched by product alone. After plan: covering `ix_evidence_latest` and `MULTI-INDEX OR` using both `(product_id, location_id, version)` movement indexes. No reservation path exists. The older 251 → 3 figure in README refers to a different historical fixture and is not a result of this audit.
